## 실제 서버 확인 범위

퇴마요새에 로그인하지 않은 연결로 초기 배너와 `[엔터를 누르세요. <안되면 X 치고 엔터>]` 안내를 수신했습니다. 계정 이름·암호·게임 명령을 전송하지 않았습니다. **실제 계정의 로그인 성공, 장시간 자동사냥, 모든 SCS 호환성은 검증하지 않았습니다.** 인식하지 못한 로그인 안내는 텍스트 화면에서 수동으로 이어갈 수 있습니다.

## 유지한 실행 상태

`iyagi-monologue-web-1`을 `http://localhost:3000`에 실행했습니다. 최초 캐릭터 목록은 비어 있습니다. 테스트용 별도 Compose 프로젝트는 정리했으며 사용자용 데이터 볼륨은 유지했습니다.

## 공지사항 로그인 순서 수정

- 사용자 확인에 따라 초기 엔터 안내에서 엔터 두 번을 전송해 시작 화면과 공지사항을 넘기고, 그 뒤 캐릭터 이름과 암호를 입력하도록 수정했습니다.
- 실제 서버에 계정 정보를 보내지 않고 엔터 두 번만 전송해 `자신의 캐릭터 이름을 넣으세요` 및 `이름은?` 안내까지 진행되는 것을 확인했습니다.
- 공지에 이름/암호라는 단어가 있어도 엔터가 먼저 전송되고, 두 번째 공지 안내에 엔터를 추가로 보내지 않는 회귀 테스트를 확인했습니다.
- 두 공지 단계를 재현한 TCP 모의 서버를 포함해 기존 앱/웹앱 전체 **39개 테스트**, 웹앱 타입 검사와 번들 빌드가 통과했습니다.

## 로그인 후 접속 체크와 광장 이동

- 로그인 성공 시 리턴 한 번과 `광장`을 차례로 전송한 뒤 실행 준비 상태로 전환합니다. 수동 로그인 완료 확인도 동일하게 처리하며 반복 성공 안내나 확인 버튼으로 재전송하지 않습니다.
- 인증 실패 시 후속 명령을 전송하지 않는 검사와, 두 캐릭터가 각각 접속 체크와 광장 이동을 마친 뒤 혼잣말 명령을 보내는 TCP 모의 서버 검증을 추가했습니다.
- HTTP 지속 실행 테스트는 로그인 초기 명령을 제외하고 혼잣말의 `계속` 명령만 집계합니다.
- 최종 전체 **41개 테스트**, 웹앱 TypeScript 검사와 서버/Worker 빌드가 통과했습니다.

## 리턴 안내 수신 후 전송하도록 순서 보정

- 로그인 성공 감지와 접속 체크 전송을 분리했습니다. 성공 감지 후 `waiting-return` 상태에서 서버의 `[리턴을 누르세요]` 문구를 기다리고, 문구가 도착한 뒤에만 리턴 한 번과 `광장`을 순서대로 전송합니다.
- 수동 완료 확인도 문구 수신 전에는 전송하지 않습니다. 수동 로그인 중 미리 받은 문구는 확인 후 처리하며, 재접속 때는 이전 접속의 문구를 재사용하지 않습니다.
- 문구의 분할 수신, 성공 안내와 같은 청크에 도착하는 경우, 환영 문구 없이 리턴 안내만 오는 경우, 대기 중 혼잣말 실행 차단을 검증했습니다.
- 최종 전체 **43개 테스트**, 웹앱 TypeScript 검사, 서버/Worker 빌드와 브라우저 JavaScript 구문 검사가 통과했습니다.

## 병합 전 출력 버퍼 암호 마스킹 수정

- 모의 TCP 서버가 합성 암호를 에코한 뒤 출력이 128,000자를 넘으면, 버퍼 앞에서 잘린 암호 뒷부분이 출력 API에 노출되는 오류를 재현했습니다.
- 완전한 암호는 버퍼를 자르기 전에 마스킹하고, 분할 수신된 미완성 조각은 다음 패킷과 함께 검사하도록 수정했습니다. API는 미완성 조각도 마스킹합니다.
- 완전한 에코와 분할 에코 모두 버퍼 경계에서 암호가 노출되지 않는 회귀 테스트를 추가했습니다.
