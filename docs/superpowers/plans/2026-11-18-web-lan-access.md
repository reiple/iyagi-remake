# 같은 네트워크에서 혼잣말 웹앱 접속

## 범위와 설계

사용자가 같은 공유기·사내망의 다른 PC에서 접속하는 방식을 선택했다. 기본 로컬 전용 동작을 유지하고 LAN 실행을 명시적으로 선택하도록 한다. 서버의 수신 주소만 바꾸면 기존 Host 검사가 LAN 요청을 거부하므로 허용할 서버 주소도 함께 설정해야 한다. 별도 프록시 설치 대신 현재 Node 서버와 Docker Compose의 설정을 확장한다.

- `WEB_ALLOWED_HOSTS`에 쉼표로 구분한 서버 IP·호스트명을 지정한다. localhost·루프백 주소는 항상 허용하고 미등록 Host와 다른 Origin은 계속 거부한다.
- Node는 기존 `LISTEN_HOST=0.0.0.0` 설정으로 LAN에서 수신한다. `start-lan.ps1`은 현재 LAN 주소를 찾아 필요한 환경 변수를 설정한다.
- Compose는 `WEB_BIND_HOST`로 호스트 공개 주소를 지정하고 `WEB_ALLOWED_HOSTS`를 컨테이너에 전달한다. 기본 공개 주소는 `127.0.0.1`이다.
- Windows 방화벽은 지정한 서버 IPv4 주소의 TCP 3000번에 대해 `LocalSubnet`에서 오는 연결만 허용한다. 현재 계정에는 관리자 권한이 없으므로 검증 후 별도 관리자 승인으로 규칙을 추가한다.
- 계정 데이터, 게임 로그인과 혼잣말 로직은 변경하지 않는다. 웹 관리용 로그인 추가나 인터넷 공개는 범위에 포함하지 않는다.

## 구현·검증

- [x] 실제 HTTP 회귀 테스트로 LAN Host 기본 거부, 명시적 허용, 같은 Origin의 API 요청, 미등록 Host·외부 Origin 거부를 검증한다. 수정 전 실패를 확인한다.
- [x] `src/server.ts`, `src/main.ts`, `compose.yaml`과 LAN 실행·방화벽 설정 스크립트를 수정·추가한다.
- [x] 사용 안내에 LAN 접속 주소, 실행 방법, 방화벽 설정과 접근 범위를 기록한다.
- [x] 전체 테스트, 웹앱 타입 검사·빌드, Compose 구성을 검증하고 변경 전체를 리뷰한다.
- [x] 실행 중인 혼잣말이 없는 것을 확인한 뒤 같은 데이터를 사용하는 서버를 LAN 수신으로 재시작한다. localhost·실제 LAN IP에서 정상 응답을 확인한다.
- [x] Windows 관리자 승인으로 해당 LAN 주소·포트의 LocalSubnet 방화벽 규칙을 추가하고 활성 상태를 확인한다.

현재 체크아웃에서 별도 브랜치 `codex/web-lan-access`로 작업한다. 이 후속 요청에서는 커밋·푸시·PR 병합을 새로 수행하지 않는다. 다른 PC에서의 실제 브라우저 접속은 해당 PC를 제어할 수 없어 사용자 확인이 필요하다.
