# 다중 캐릭터 혼잣말 웹앱

사용자 요구: 기존 앱의 엔진을 기반으로 별도 폴더에 웹앱을 만들고 Docker / Docker Compose로 실행한다. 캐릭터 이름과 암호로 추가하며 캐릭터별 접속, 혼잣말 실행, 텍스트 화면 버튼을 제공한다. 텍스트 입력과 출력은 사용자가 열 때만 다이얼로그로 표시한다. 웹페이지와 다이얼로그를 닫아도 실행은 유지한다.

## 구현 선택

- `web-monologue/`에 Node.js HTTP 서버와 한국어 웹 UI, Dockerfile, compose.yaml을 둔다. 기존 `Connection`, `ScriptService`, Worker를 번들에 재사용한다.
- 브라우저 단독 실행은 탭 종료 후 실행과 Telnet TCP 접속 요구를 만족하지 못한다. 기존 Electron 앱을 여러 개 띄우는 방식은 웹 기반 관리 요구를 만족하지 못한다. 따라서 컨테이너의 서버가 연결과 Worker를 소유한다.
- 캐릭터마다 독립 Connection / ScriptService / 출력 버퍼 / 로그인 상태를 둔다. HTTP 요청과 폴링은 상태만 관찰하며 브라우저 종료가 세션에 영향을 주지 않는다.
- 캐릭터마다 SCS와 필요한 H 파일을 업로드하고 번역한 다음 실행한다. 실행 중에는 소스를 덮어쓰지 않는다. 정지, 접속 종료, 캐릭터 삭제도 명시적으로 제공한다.
- 텍스트 화면은 기본적으로 닫혀 있다. 게임 명령, 비밀 입력, 혼잣말 입력 요청과 출력 확인을 이 다이얼로그 안에서 처리한다. 입력 요청은 닫힌 창을 자동으로 열지 않으며 목록에 대기 표시를 한다.
- 접속 버튼은 알려진 이름/암호 프롬프트에 대응한다. 인식할 수 없는 안내는 텍스트 화면에서 수동으로 이어갈 수 있다. 로그인 성공이 확인되기 전 혼잣말 전송은 차단한다.
- 캐릭터와 업로드 소스는 볼륨에 보관한다. 암호는 AES-256-GCM으로 암호화하고 키도 같은 보호된 볼륨에 보관한다. API 응답과 로그에는 암호를 넣지 않는다. 볼륨과 키에 접근 가능한 관리자로부터의 암호 보호는 제공하지 않는다.
- Compose는 호스트 `127.0.0.1:3000`으로만 공개한다. 데이터 볼륨, 비루트 사용자, healthcheck, `restart: unless-stopped`를 사용한다. 컨테이너/PC 종료 시 TCP와 Worker는 종료되며 재시작 후 자동 게임 접속/스크립트 재개는 하지 않는다.

## 검증

실제 TCP 모의 서버와 Worker로 두 캐릭터의 분리, 이름/암호 로그인, 브라우저 요청 종료 후 지속 실행, 명시적 중지, 저장 후 복구, 암호 비노출, 헤더 경로 제한을 확인한다. UI에서 다이얼로그 열기/닫기와 모바일 폭을 검증한다. 실제 게임 계정과 자동사냥은 검증에 사용하지 않는다.
