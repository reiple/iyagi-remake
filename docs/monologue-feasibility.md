# 혼잣말 번역·실행 기능 구현 가능성 조사

## 결론
소스(.SCS 및 .H)를 읽어 새 앱의 내부 실행 형식으로 번역하고 실행하는 호환 엔진은 구현 가능하다. 기존 .SCF 바이너리의 직접 실행과 원본과 동일한 SCF 생성은 별도 가상 머신/바이트코드 분석이 필요하며 현재 보장하지 않는다. 이번 작업은 조사만 수행했고 앱 코드는 변경하지 않았다.

## 원본에서 확인한 근거
- C:\KSR\MULTI\SCF: .SCS 27개, .SCF 209개, .SCP 15개, .H 4개.
- I.H와 ENGLISH.H 및 GAME.SCS를 Windows code page 1361(조합형)로 정상 해독. README와 SCP 예시는 CP949. 파일별 인코딩 선택이 필요하다.
- ENGLISH.H의 한영 대응: main/여기부터, if/만약, else/아니면, while/맴돌이, for/여러번, return/되돌리기, int/정수, char/문자, str/글월, include/포함, define/정의.
- I.H: 보내기=asyncputs 별칭; 글마중, 제한글마중, 글마중제한시간, 정수보내기, 지연, 중지, 문자열/화면/파일/시스템 함수 선언.
- GAME.SCS: 배열, 변수, 중첩 for, strstr, 메모리글자읽기(-1,offset), 제한글마중 및 보내기 사용. 화면의 특정 문자열을 검사하고 응답을 기다리는 실제 예시가 있다.
- NO_SKILL.H: 퇴마요새 명령으로 보이는 전투/이동/음식/장비 관리 루틴. 전역 변수, 문자열 배열, 사용자 함수, 조건/반복, 논리·나머지 연산 사용. 외부의 전체방수와 개별 초기화 함수에 의존하여 헤더 단독 실행은 불가능하다.
- NO_SKILL.H의 보내기 호출은 부분 문자열을 여러 번 송신하고 마지막 |로 마무리한다. 줄 단위 명령 API를 호출마다 사용하면 동작이 달라진다.
- NO_SKILL.H 주석은 지연(500)을 5초로 설명한다. 1 단위=10ms라는 단서지만 원본 실행으로 확인하지 않았고 제한글마중 시간 단위도 별도 확인 대상이다.
- AA01.SCF는 텍스트 소스가 아닌 바이너리이며 ASCII 영역에 Script File. Ver 7,0 헤더가 있다. 명령어 집합, 내장 함수 번호, 값 표현은 미해석.
- BA01.SCP/BOB.SCP는 proc main, waitfor, transmit, endproc 구조로 SCS와 다른 문법이다. 같은 파서로 처리한다고 가정하면 안 된다.
- iyagi.chm을 .tools/iyagi-help에 추출했다. menu6.html은 혼잣말을 C 유사 언어로 설명한다. script.html은 script.chm::/start.html을 참조하나 원본 폴더에 script.chm은 없다.

## 권장 구현 범위
1. 소스 불러오기(조합형/CP949/UTF-8), 편집, 번역 결과/줄 번호 오류 표시.
2. 한국어·영어 키워드를 토큰화하여 동일 AST로 변환. 주석, include, define, 변수, 배열, 사용자 함수, 조건, 반복, return/break 지원.
3. AST 또는 자체 명령어로 실행. JavaScript eval 또는 원본 DLL 호출을 실행 기반으로 삼지 않는다. 원본 SCF와 혼동되지 않는 내부 형식을 사용한다.
4. 머드 필수 함수: 보내기/정수보내기, 글마중/제한글마중, 지연, 문자열 처리, 중지. 소스에 사용된 함수 목록을 먼저 검사하고 미지원 함수를 명시한다.
5. 부분 송신과 |의 CR 처리, 수신 커서, 타임아웃 및 기존 화면 검사 의미를 구현한다. 빈 |를 버리면 원본 예시와 호환되지 않는다.
6. 별도 worker에서 실행하고 전송·화면 읽기 같은 제한된 호스트 API만 허용한다. 강제 중지, 명령량/메모리 상한, 연결 종료 시 취소, 일시정지/재개 및 실행 위치 표시를 제공한다.
7. 원본 시스템 종료/포트 접근/메모리 접근 등은 일반 OS 권한으로 제공하지 않는다. 화면 메모리 읽기는 가상 터미널 상태의 읽기 API로 대응한다.

## 현재 앱에 필요한 변경
- src/core/connection.ts: send는 호출마다 CRLF를 붙이므로 혼잣말용 부분 송신 경로 추가 필요.
- src/core/commands.ts: 현재 expand는 빈 |를 제거하고 동기 명령 리스트만 만든다. 혼잣말 스트림 의미를 별도로 구현해야 한다.
- 수신 이벤트와 터미널 화면 스냅샷을 실행 엔진에 공급해야 한다. 글마중이 이미 수신된 버퍼를 소비하는 방식은 원본 비교로 확정한다.
- 설정/실행 UI 및 preload IPC에 제한된 스크립트 API 추가.

## 호환 판정과 검증
소스 호환 / 함수별 동작 호환 / SCF 바이너리 호환을 별도 표기한다. 원본에서 최소 스크립트를 번역·실행해 지연 시간, | 및 부분 송신, 문자열 변경과 함수 인수, 배열/정수 의미, 대기 반환값을 비교해야 한다. 모의 MUD 서버에서 동일 입력/출력 순서와 시간 범위를 비교하고 무한 반복 중 강제 중지를 검증한다. 실제 게임에서의 자동 명령 실행은 이 조사에서 수행하지 않았다.

## 남은 자료
상세 매뉴얼 script.chm과 실제 사용 중인 진입 .SCS 파일 및 포함 파일이 있으면 호환 범위를 더 정확하게 산정할 수 있다. 현재 NO_SKILL.H는 공통 루틴이므로 전체 동작을 검증할 충분한 단독 프로그램이 아니다.
